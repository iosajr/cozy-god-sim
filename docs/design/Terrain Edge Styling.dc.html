Terrain look-dev · edge language

Soft lowland lips, hard upland cliffs

Your probe reads flat for one structural reason: every terrace is the same 1.5 units tall, and every edge is the same vertical box face. Pokémon and Don't Starve both terrace — they differ in what happens at the step. The fix is a single rule applied at mesh time: treat an edge by how far the land actually drops there, and let step height grow with altitude so the rule sorts lowlands and cliffs for you.

Pokémon B/W — the lip

Plateaus are one or two units apart and the face is short, warm, and slightly angled. The silhouette stays readable because the grass rolls over a lit top edge rather than ending in a hard corner. Steps are frequent and shallow.

Don't Starve — the wall

One enormous drop instead of many small ones. The face is near-black at its base, the top edge carries a painted dark rim, and the whole palette is desaturated slate and umber. Height is spent in few, tall steps.

Your probe — uniform stairs

Constant terrace_step, box columns, one green and one brown. Every edge is identical, so the eye reads contour lines on a pancake — no lowland, no cliff, no scale cue.

01 · GROWING STEPS

Step height scales with altitude: step(i) = base × (1 + growth × (i − sea)). Coastal plains stay walkable, highlands become dramatic.

02 · ONE EDGE RULE

Per cell edge, measure the real drop. Under the threshold it becomes a bevelled skirt; over it, a vertical face. No biome authoring — the terrain decides.

03 · PAINTED RIM

Top-face corners sitting over a drop get darkened ~22% in vertex colour. That single multiply is what buys the hand-inked Don't Starve outline, with no shader.

04 · ONE MESH

Quads only where geometry is visible, welded into a single vertex-coloured ArrayMesh — far cheaper than 65k box instances, and it takes per-vertex colour.

Wiring it into your probe

The full builder is in TerraceMeshBuilder.gd — drop it beside terrain_noise_probe.gd. It replaces _build_cliff_multimesh() and _build_grass_multimeshes() entirely; your HeightMap, bands, camera rig and trees stay as they are.

@export var terrace_step: float = 1.4      # was 1.5, now only the LOWLAND step
@export var cliff_growth: float = 0.22     # each step above sea is this much taller
@export var soft_drop: float = 2.4         # drops under this bevel, over this cliff
@export var bevel_lip: float = 1.1         # keep under cell_size * 0.45
@export var sea_level_band: int = 2

var _terrain_instance: MeshInstance3D
var _heights: PackedFloat32Array

func _rebuild_terrain_meshes() -> void:
    if _terrain_instance != null:
        _terrain_instance.queue_free()
    for instance in [_trunk_instance, _canopy_instance]:
        if instance != null:
            instance.queue_free()

    _heights = TerraceMeshBuilder.level_heights(
        _bands.size(), terrace_step, cliff_growth, sea_level_band)

    var mesh := TerraceMeshBuilder.build_mesh(
        _levels, grid_cells, grid_cells, cell_size,
        _heights, sea_level_band, soft_drop, bevel_lip, _current_seed)

    _terrain_instance = MeshInstance3D.new()
    _terrain_instance.name = "Terrain"
    _terrain_instance.mesh = mesh
    _terrain_instance.material_override = TerraceMeshBuilder.make_material()
    add_child(_terrain_instance)
    _build_trees()

# heights are no longer level * terrace_step — everything that placed things
# on the ground (trees, water, spawn points) reads the table instead:
func _cell_top_y(level: int) -> float:
    return _heights[level]
Water level follows too

Set water_level_y = _heights[sea_level_band] - 0.15 instead of the hard-coded 2.25, or the sea will drift as you tune the step.

Scale comes from the step, not the grid

At 256 cells × 4 units your island is 1 km wide but only ~20 units tall. Growth 0.2–0.3 pushes peaks past 60 units, which is where the silhouette starts reading as landscape.
